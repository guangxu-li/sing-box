`direct` 入站是一个隧道服务器。

### 结构

```json
{
  "type": "direct",
  "tag": "direct-in",

  ... // 监听字段

  "network": "udp",
  "override_address": "1.0.0.1",
  "override_port": 53,
  "dns_hijack_loopback": false,
  "dns_hijack_exclude_source": ""
}
```

### 监听字段

参阅 [监听字段](/zh/configuration/shared/listen/)。

### 字段

#### network

监听的网络协议，`tcp` `udp` 之一。

默认所有。

#### override_address

覆盖连接目标地址。

#### override_port

覆盖连接目标端口。

#### dns_hijack_loopback

!!! question "自 sing-box 1.15.0 起"

!!! quote ""

    仅支持 macOS。

通过加载 pf `rdr` 规则，将系统的环回 DNS 端口重定向到此监听器。

此项从占用 `127.0.0.1` 并将自身注册为系统解析器的 VPN 客户端手中夺回 `:53`。隧道无法通过路由捕获环回地址，
因此 pf 是唯一可行的机制。

规则被加载到 `com.apple/` 下的锚点中，标准的 `/etc/pf.conf` 已通过其通配锚点行对其求值，因此无需修改任何
系统配置。当该文件不存在时此项将拒绝启动，因为那时锚点永远不会被求值，重定向会静默失效。

仅重定向此监听器实际开启的协议，并分别指向其实际绑定的端口。`listen` 必须为环回地址，且不能为未指定地址，
因为无法确定监听器在哪个环回地址上应答。

规则在此监听器开始接受连接后加载，并在正常关闭时移除，因此新建连接不会被重定向到无人应答的端口。
已经通过重定向建立的流可能比规则存活更久，因为 pf 会为转换规则保留状态直至其过期。

规则存在于内核中而非进程中，因此崩溃会将其遗留下来，DNS 将继续被重定向到已不再监听的端口。
以相同端口重启会重新加载同一锚点并再次接管重定向。锚点以实际绑定的端口命名，因此当 `listen_port` 交由系统分配时，
重启可能获得不同的端口，此时残留的锚点需要通过 `pfctl -a <锚点> -F nat` 手动移除。

#### dns_hijack_exclude_source

!!! question "自 sing-box 1.15.0 起"

不重定向来自此源地址的查询。

当 sing-box 通过其正在捕获的同一环回端口解析上游时必须设置，否则它自己的查询会被路由回自身。
请填写上游 DNS 服务器的拨号器所绑定的地址。

pf 每条规则只接受一个源地址，因此此项仅应用于匹配的地址族。
